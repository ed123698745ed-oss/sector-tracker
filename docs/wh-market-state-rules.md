## 可同步規則正文

### 1. 用途與限制

市場狀態描述全市場上市櫃普通股的歷史極端程度，供頁面觀察與狀態改變時的 LINE 提醒。分數是歷史百分位，不是事件發生機率。常態不表示市場沒有風險。過去每年的狀態改變次數不是未來次數的上限。不得把本功能表述成進出場訊號或已核准策略。

### 2. 資料與計算順序

每個交易日、只用該日（含）以前的輸入，順序固定為：

1. **當日原始因子**（窗的右端是當日，不讀當日之後）：
   - 加權指數 5 日、20 日報酬。指數缺值時沿用較早的收盤，不沿用未來。
   - 加權指數日報酬的 20 日標準差（母體標準差，除以窗內筆數）。
   - 加權指數對 60 日簡單均線的乖離（收盤／均線 − 1）。
   - 普通股成交值的 20 日均值 ÷ 250 日均值。
   - 5 日跌停家數占比合計、5 日漲停家數占比合計（當日家數／當日有效家數，缺有效家數則該日為缺）。
   - 收盤離近 250 日高點（含當日）≥20% 的家數占比。
   - 前 5 大成交值（排除台積電 2330）占其餘普通股成交值的比重，再取 5 日平均。
2. **方向**：下跌用的 5 日、20 日報酬先取負號，所以跌得越多、百分位越高。其餘因子數值越大越高。
3. **Expanding 百分位**：自 `2005-01-01` 起至當日（含）已出現的非缺值。當日百分位 = 歷史中 ≤ 當日值的筆數 ÷ 歷史筆數（`bisect_right`）。`2005-01-01` 之前的因子值不進入這個歷史。歷史未滿 `MINHIST = 250` 筆則該因子百分位為缺。
4. **合成分數**：下跌是 5 個百分位的算術平均，上漲是 4 個，資金集中就是該因子百分位。任一個成分缺值，整條分數為缺，不拿其餘成分補平均。
5. **狀態**：用未四捨五入的分數套用第 4 節。寫進 `wh.json` 的分數再用 Python 3 `round(分數, 3)`（銀行家捨入）到小數三位。網頁把這三位小數顯示成整數百分數，只供閱讀。

因此：頁面上的 85 可能對應實際未達進入門檻的原始分數。核對進出要用未捨入分數，或用程式重算，不要用頁面整數百分數反推。

### 3. 歷史起點與暖機

| 項目 | 值 |
| --- | --- |
| 百分位歷史起點 | 2005-01-01（含） |
| MINHIST | 250 個非缺值交易日 |
| 規則版首次有下跌／上漲分數 | 2006-02-10（以 stock_date=20261029 的 `docs/wh.json` 為準） |
| 資金集中分數 | 可早於 2006-02-10；有分數日的 5093 口徑仍以下跌分數已存在為準 |

2004 年的行情可進入滾動窗（例如 250 日高點），但不進入百分位樣本。暖機完成前狀態保持常態。

### 4. 門檻、遲滯、優先序、缺值

現行規則 id：`2026-10-29`。進入與退出都是「大於或等於」。

| 狀態 | 代號 | 進入 | 退出 |
| --- | --- | --- | --- |
| 下跌瘋狂 | -1 | 0.85 | 0.72 |
| 上漲瘋狂 | 1 | 0.87 | 0.80 |
| 資金集中炒作 | 2 | 0.985 | 0.96 |
| 常態 | 0 | — | — |

判定順序：

1. 若前一狀態是非常態，且**該狀態自己的分數**仍 ≥ 退出門檻，維持前一狀態。此時不看其他分數。所以已在上漲時，即使下跌已達進入，只要上漲仍 ≥ 0.80 就維持上漲。遲滯優先於下面的競合順序。
2. 否則當日先視為常態，再依序檢查進入門檻：下跌、其次上漲、最後資金集中。先達到的勝出。
3. 因此可以在同一天退出並直接進入另一狀態。例如下跌分數低於 0.72 且上漲分數 ≥ 0.87，當日改為上漲。
4. 分數缺值（暖機不足、家數為 0、窗內有缺）視為**沒有**達到該側門檻。已在非常態時，自己的分數缺值會離開該狀態；若同日另一分數達到進入門檻，就改入該狀態，否則回到常態。
5. 三個分數都缺，狀態為常態。

恰等於進入門檻會進入；恰等於退出門檻會維持。恰小於門檻（下一個較小的浮點數）不會進入、也不會維持。可重現案例在 `docs/wh-market-state-evidence/state-machine.md`，指令 `python3 -m unittest tests.test_wh_extreme`。

### 6. 推播

正式推播**維持啟用**。只在最新兩個交易日的狀態不同時推。訊息含「只供觀察，不是交易訊號」，不含買賣建議。

| 項目 | 規則 |
| --- | --- |
| 排程 | `.github/workflows/daily.yml`。台北時間週一至週五 13:52、14:12、14:32、14:52、15:12、15:42、16:20、18:20。當日 `data/quotes/YYYYMMDD.json` 已存在則跳過抓取與重算。 |
| 資料就緒 | `wh.json` 的 `stock_date` 等於最後一個交易日；state／三個分數與日期等長；當日行情檔存在；檔內門檻與程式現行門檻一致；排程傳入的預期日與 `stock_date` 一致。非常態但該側分數缺值則不送。 |
| 同日去重 | `data/wh_notify_ledger.json` 以（資料日、前態、新態）記錄。已有 `sent` 則不重送。狀態沒變本來就不推。 |
| 失敗重試 | 同一次執行內最多送 3 次（間隔 2 秒、4 秒）。仍失敗寫 `result=failed`。之後排程若當日行情已存在，只跑 `--retry-only`，且只補送 ledger 裡已有失敗紀錄的同一事件。沒有紀錄不補送，避免舊版已送過但當時還沒有 ledger 時再送一次。 |
| 未設定 LINE | 只印出、不寫成已送達，也不寫入 ledger。 |
| 紀錄內容 | 結果、次數、台北時間、規則 id、分數、訊息正文與訊息 sha256。收件者只記 `configured` 或 `unset`。不寫 token、user id。錯誤文字若含這兩項會改成 `[redacted]`。 |
| 試跑 | `python3 scripts/wh_notify.py --dry-run` 不送出、不寫 ledger。`python3 scripts/wh_notify.py --preview-test` 只印帶「測試」的示範訊息。 |

推播失敗且當日 git commit 也失敗時，乾淨的 checkout 不會留下 ledger，下一次排程會因行情檔已存在而走 `--retry-only` 且找不到失敗紀錄，因而不補送。這個缺口要人工重跑（先讓 ledger 有失敗列，或在確認尚未送達後刪除「已處理」標記再跑正式步驟）。不要為了補送而關掉正式推播。

### 7. 時點假設與尚未能驗證的範圍

在**現在這份** `docs/wh.json` 與 `data/quotes` 上，`python3 scripts/wh_extreme_audit.py` 會把每個交易日的輸入截到該日（含）再呼叫 `compute`，並與完整序列的同一天比較。這證明分數與狀態是該日以前（含當日）輸入的函數。

仍不能驗證、必須分開寫的範圍：

- 沒有各歷史日收盤當下的行情、指數與股票母體快照。現存檔案可能含事後修正、補檔，以及減資、分割、除權息參考價補算。
- 普通股是現存行情檔中 4 碼數字、不以 0 開頭、排除 91 開頭的代號，不是當日凍結的成分股影像。
- 2009 年以前加權指數點位來自月檔 FMTQIK 的當日收盤；公式不讀該日之後的列，但檔案可能是後來下載的。`data/quotes` 的 `taiex` 欄是加權漲跌%，不是指數點位，不進入本計算。
- 跌停家數與離高點分布沿用已建置的 `wh.json`。本次沒有把整條 `wh_prices`／`wh_build` 對每個歷史前綴再跑一次。程式的滾動窗是往回看。
- 收盤檔公布前的盤中值沒有另存。狀態只在該日行情檔存在之後計算。

### 8. 事件表

占比的欄位定義見 `config/wh_extreme_events.json` 與 `docs/wh-market-state-evidence/events.md`。

- 起日、迄日都納入（閉區間）。不是交易日的端點不平移。
- 有效交易日 = 區間內下跌分數不是 null 的交易日（與 5093 口徑相同）。
- 占比 = 該狀態天數 ÷ 有效交易日。
- **原交審窗未驗證／待 Ed 補起訖。** repo 沒有 Ed 交審表的起迄。在補上之前，審計程式不會用自訂窗填原表。
- Eve 自訂日曆窗只放在對照區，用來重現審查時的抽查，不是原表。

**「2021 航運」與「資金集中」不可等同。** 資金集中是排除台積電後的前五大成交值占比，不是航運族群狀態。不能用 2021 年 `state=2` 的天數去核對或代替航運 91%。

### 9. 年度切換與 5093／695

定義與全表：`docs/wh-market-state-evidence/yearly.md`。重跑會覆寫該檔。

- 切換 = 相鄰兩個交易日 `state` 不同，計入新狀態那天的西元年。與推播的 `state[-2] ≠ state[-1]` 同一口徑。
- 有分數日 = 下跌分數不是 null。`stock_date=20261029` 時有分數 **5093** 日、非常態 **695** 日（13.65%）。此後每增加一個交易日，這兩個數字會變，必須連同 `stock_date` 一起寫。
- 約 8.1 次／年的分母是「至少有一次切換的年份」，不是全部有資料的年份。切換零次且有分數的年份（在該快照為 2013、2014、2016、2017、2019、2023）不是缺資料。
- 2004、2005 無分數（2004 在百分位起點之前，2005 暖機未滿 250）。2006 年分數自 2006-02-10 起，該年分數不完整。2026 年資料止於快照日，是不完整年。中間年份有沒有缺交易所交易日，未與行事曆逐日勾稽。
